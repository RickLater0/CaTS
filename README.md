**ЛР1 Java. Разработка класса структуры данных**

Портировать одну из структур данных (СД), приведенных в [cprog](https://ermak.cs.nstu.ru/cprog).  
**СД хранит данные произвольного типа:**

* Количество хранимых типов – не менее 2, обертка для 1-3 и 4-12
* Экземпляр СД хранит объекты только одного типа (например, только целые или только строки)

**Набор операций для структуры данных:**

* добавление в конец, получение, вставка и удаление по логическому номеру (индексу). Логический номер – порядковый номер хранимого элемента в соответствии с последовательностью обхода структуры данных (перебора элементов)
* для исходно упорядоченной (например, «двоичное дерево») вставка с сохранением порядка, получение и удаление по логическому номеру индексу)
* Итератор forEach – 
  * для Java: интерфейс обратного вызова с методом void toDo(T v), итератора получает ссылку на интерфейсный объект (анонимный класс), обходит структуру данных и вызывает метод для каждого выбранного элемента. 
  * В Scala – формальный параметр = функция.
* сортировка, для исходно упорядоченной – балансировка = создание экземпляра структуры данных с равными размерностями компонент (например, сбалансированное дерево, либо список списков со списками нижнего уровня равной длины)
* сериализация хранимых данных в текстовый (двоичный) файл в формате по выбору – XML, JSON, собственный двоичный (сохранение и загрузка)
Структуру данных реализовать в виде шаблона или реализации интерфейса,
работающего с произвольным типом данных (ТД).

Разработать оконное приложение, работающее со структурой данных. Функции:  
отображение состояния (содержимого), все операции, сохранение и загрузка из текстового (двоичного) файла


Обеспечить возможность настройки приложения на работу с выбранным из списка типов данных (как минимум, 2).  
Требуется, чтобы для добавления нового ТД нужно было бы создать класс ТД, присоединяющий общий для ТД интерфейс и добавить экземпляр этого класса в фабрику.
Никакие другие изменения в код не допускаются.

### Реализация

#### lab-data

В модуле data ([com.redwood.data](lab-data/src/main/java/com/redwood)) реализован интерфейс [UserType](lab-data/src/main/java/com/redwood/interfaces/UserType.java), который "делает с типами то, что надо".   
В этом модуле так же объявлены 3 типа (в виде record), которые реализуют интерфейс UserType :

* [VectorPolar](lab-data/src/main/java/com/redwood/dataobj/VectorPolar.java) - Вектор полярном в виде. Градус измеряется в радианах, задаётся строкой вида "(0.0;0.0)"
* [StringType](lab-data/src/main/java/com/redwood/dataobj/StringType.java) - Обёртка над строкой, что реализует пользовательский интерфейс
* [IntegerType](lab-data/src/main/java/com/redwood/dataobj/IntegerType.java) - Обёртка над целочисленным числом (int), что реализует пользовательский интерфейс

В этом модуле написана фабрика [UserFactory](lab-data/src/main/java/com/redwood/factory/UserFactory.java). Фабрика возвращает вектор имен типов, на основе которых строится выпадающий список для выбора текущего ТД во вьюшке. По имени выбранного ТД фабрика возвращает объект-прототип.

#### lab-view

В модуле view ([com.redwood.view](lab-view/src/main/java/com/redwood)) находится GUI с динамическим отображением узлов списка.  
В интерфейсе пользователю доступно:

* удаление элемента по содержимому, по индексу
* вставка в конец, по индексу
* получение объекта по индексу
* сортировка
* выбор хранимого ТД
* сохранение/загрузка СД в файл
* взаимодействие с коллекцией через итератор

### Особенности реализации (в соответствии с ТЗ)

* **Итератор**:
    * В Java реализован через интерфейс обратного вызова `Consumer` (метод `forEach`).
    * В Scala реализован через передачу функции высшего порядка в качестве формального параметра.
    * В Kotlin реализован через стандартный `MutableIterator` (или лямбду).
* **Сериализация**: Выгрузка и загрузка реализована в формате **XML** с помощью библиотеки **Jackson 3** (в каждом модуле используются свои `XmlMapper`).
* **Полиморфизм**: Выбор реализации (Java/Kotlin/Scala) осуществляется через класс `UserListProvider`, который возвращает объект типа `IUserList<T>`. Это позволяет GUI-модулю (`lab-view`) работать с любой реализацией через единый интерфейс.

### Сборка и тестирование

#### Сборка 

Требования:

* Java 25
* Maven 3.10.0
* Scala 3.9.0
* Kotlin

Проект собирается и запускается через module-path. Сама сборка происходит через команду:  
```bash
mvn clean install
```
Запуск:  
```bash
cd lab-view
mvn javafx:run
```
Или
```bash
cd lab-view/target
java -jar --enable-native-access=ALL-UNNAMED lab-view-1.0.jar
```
